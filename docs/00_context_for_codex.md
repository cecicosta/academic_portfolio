## Portfolio Principles

- Write in professional English with a clean academic tone.
- Use Cecilia Lis Costa as the current name and identity.
- Avoid marketing-style language, exaggeration, and broad claims that are not
  supported by evidence.
- Prefer Markdown as the source format.
- Make each report reusable: context, role, contributions, skills, and evidence
  notes should be clear.
- Keep the repository as the source of truth; application packets can later
  select only the strongest and most relevant material.

## Evidence Standards

Each report should identify the supporting evidence and state its limits. Use the
following categories:

- Confirmed by local evidence: supported by a file in `sources/`.
- Supported by public reference: supported by an external official page,
  publication page, or DOI. Capture or archive these later where possible.
- Draft/source note: supported by a locally drafted overview, but not yet by a
  primary official source.
- Needs confirmation: mentioned in working notes but not yet verified from a
  primary source.

Scanned files that do not expose text should be treated as evidence by file
identity until OCR or manual review is completed.

Facts must be distinguished from inferences. Recommendation letters may be used
as supporting evidence for responsibilities that are not publicly documented, but
the report should make clear that the role-specific claim is supported by the
letter rather than by a public source.

Whenever uncertainty exists, explicitly state it instead of making assumptions.

## Report Structure

Reports should be independently understandable. When the material supports it,
use the following structure:

- overview;
- objectives or institutional context;
- project or program context;
- `My Role and Contributions`;
- skills demonstrated or developed;
- impact or outcomes;
- references;
- supporting evidence and evidence limitations.

Not every report needs every section, but missing or weak evidence should be
visible in the evidence notes.
